False claim vs real bottleneck

Claim: “Parsing is slow because pdfplumber is single-threaded — switch to docling.” False. Both Python services are FastAPI + uvicorn (async). The real bottleneck was a BullMQ document-job race causing duplicate work and last-writer-wins chunk loss.

1. Document processing timeline

Before: two concurrent chunking jobs for the same document overlap and overwrite each other’s chunks. After: pessimistic row lock forces clean sequential critical sections.

2. Embedding model drift

Mixed-model vectors (ada-002 vs text-embedding-3-small) share 1536 dims but are not comparable. Scatter shows cosine similarity of a fixed query against stored chunks — mixed corpus silently degrades recall until we filter by embeddingModel.

4. WebSocket subscription leak

Each chat-message instance previously retained a live WebSocket subscription after scroll-away. Fix: DestroyRef + takeUntilDestroyed.
